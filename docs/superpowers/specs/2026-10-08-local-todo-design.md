# 本地 Todo 桌面程序：产品与技术设计

日期：2026-10-08。状态：已按用户八项选择形成开发方案；代码工程位置在实现前确定。本文只规划，不启动实现。

## 1. 产品目标与已确认范围

面向个人日常工作，提供无需账户、离线可用的任务管理，核心闭环是录入任务 → 安排与查看 → 截止提醒 → 完成与回顾。

已确认：
- 第一版为 Windows 桌面版。
- 使用 Rust 后端与网页技术界面，采用 Tauri。
- 本日、本周、本月按截止日期自动归类，另支持安排到今天。
- 关闭窗口后驻留托盘，使用系统通知。
- 包含每日、每周、每月重复任务，数据完全本地。

已确认的细化选择：
- 按日历生成每期实例，旧实例未完成时保留为逾期；每月31日遇短月取月末。
- 支持多个提前天数，默认提醒时刻09:00，恢复运行时合并补发。
- 中文简洁侧栏与列表、浅色/深色主题、优先级、搜索和子任务。

建议工程独立于当前 Fortran 项目，暂用名称 LocalTodo。本文档暂存在当前工作区；实现前确定新工程的绝对路径。首版目标环境为 Windows 10/11 x64，其他架构和系统后续扩展。

## 2. 功能与界面

| 功能 | 首版行为 |
| --- | --- |
| 任务管理 | 新建、编辑、完成、恢复未完成、删除与回收站恢复 |
| 任务字段 | 标题必填，备注、优先级、计划日期、截止日期/时刻、提醒与重复规则可选 |
| 任务导航 | 收集箱、本日、本周、本月、指定日期、逾期、已完成、回收站 |
| 排序与筛选 | 默认截止时间升序、优先级降序、创建时间升序；可筛优先级和完成状态 |
| 快速操作 | 快速录入、安排到今天、完成勾选；Ctrl+N新建、Ctrl+F搜索、Esc关闭编辑 |
| 设置 | 主题、默认提醒时刻、时区、登录启动、通知测试、数据备份与恢复 |
| 子任务 | 单层清单，父任务完成时未完成子项一并完成；恢复父任务不自动恢复已完成子项 |

界面采用左侧导航、中间任务列表、右侧可关闭详情面板。任务行展示勾选框、标题、截止日期、优先级和重复标识；逾期同时使用文字和颜色标识。日期通过选择器输入，首版不做自然语言解析。提醒失败在应用内展示可处理的状态。

首版不包含云同步、账户、团队协作、附件、复杂项目管理、AI功能和移动端。备份采用版本化JSON导出及SQLite一致性快照，不把同步能力混入本地首版。

## 3. 日历与截止规则

所有视图查询同一任务集合，任务出现在多个视图时仍是同一条记录，完成状态同步。

- 本日：今天截止，或计划日期是今天的未完成任务。安排到今天只修改计划日期，不改变截止日期。
- 本周：截止日期位于当前周一至周日的未完成、未逾期任务。
- 本月：截止日期位于当前自然月的未完成、未逾期任务。
- 指定日期：查看选中日期截止的任务；新建时可设置任意合法日期。
- 收集箱：无截止日期且无计划日期的未完成任务。
- 逾期：当前时刻达到截止边界且未完成。各主视图上方显示逾期数量，可展开同一列表。
- 无截止日期但计划在未来的任务可通过搜索及计划日期筛选查看。
- 已完成默认不占待办列表，在已完成视图查看。

只有截止日期时，截止边界为该日期次日00:00，达到边界即逾期；界面显示“当天结束前”。指定时刻时，达到该时刻即逾期。不用23:59:59表达全天截止，避免精度漏洞。

示例：2026-10-08创建任务，截止2026-10-12，它进入本月，但不进入本周（10月5日至11日）；安排到今天后也进入本日。跨月的一周仍按完整周查询。

日期保留本地日历语义，事件时间存UTC。首启获取系统时区并保存为应用时区，后续不静默跟随系统时区改变；用户更改应用时区后重建未发提醒。夏令时不存在的本地时刻向后移动至下一个合法时刻；重复时刻取较早一个。

## 4. 重复任务规则

重复模板和具体任务实例分开保存，完成一期不完成整个模板。

- 每日：从开始日期起每天一期。
- 每周：从开始日期起，按选中的一个星期几每周一期；首版不做任意间隔和多星期几。
- 每月：固定日号每月一期。31日遇2月生成2月末实例，3月仍回到31日，不按上次日期继续递推。
- 开始日期必填，结束日期可选且包含当日；首个实例不能早于开始日期。
- 未完成实例保留为逾期，新一期继续生成。删除/跳过单期保留实例标记，不能被后台重新生成。
- 编辑时区分“仅本次”与“本次及以后”；后者以所选实例日期拆分模板，取消未来旧实例和提醒，历史已完成实例保持不变。
- 子任务按模板复制到每个实例，完成状态互相独立。

实例按需生成到查询结束日或未来最远提醒需要覆盖的日期，取较远值；后台至少每日推进一次。设(series_id, occurrence_date)唯一约束，每批最多100条，保存推进游标，长期未启动后分批补齐且不阻塞界面。通知使用合并策略，避免积压通知轰炸。

## 5. 提醒规则

- 单个任务可设置多个不重复的提前天数，范围0–365整数；0表示截止当天。提醒默认关闭，由用户启用。
- 基于截止日期减去N个日历日，在指定本地时刻提醒，默认09:00，不使用N×24小时计算。
- 例：10月20日截止，提前3天、1天、当天09:00，对应10月17、19、20日09:00。
- 若任务指定08:00截止，提醒时刻不能晚于08:00；表单要求调整，后端重复校验。
- 没有截止日期不能启用截止提醒。首次设置时已经过去的提前提醒不逐条补发；若任务仍未完成且存在已过提醒，展示一次“提醒时间已过”的应用内状态，可立即发送一次合并提醒。
- 正常运行时按最近的提醒唤醒，最多每30秒重新核对墙上时钟。启动、恢复睡眠、编辑任务、修改时区后重算。
- 休眠或退出造成错过提醒，恢复运行时将未处理提醒合并为一条摘要；对应任务在应用内提醒中心可查。
- 完成、删除、修改截止日期或提醒规则时，在同一事务中取消旧提醒并生成新版提醒。重复任务每一期独立提醒。
- 应用内提醒记录与系统通知分开：系统调用成功只表示已提交，不能保证用户看到。通知权限关闭或勿扰状态下仍保留应用内提醒。
- 系统提交采用持久化待发送记录和唯一键防止常规重复；崩溃发生在提交系统后、落库前时可能重复一次，不宣称跨数据库与操作系统严格恰好一次。

关闭窗口隐藏至托盘，不停止提醒。托盘菜单提供打开、快速新建、退出。选择退出后不再提醒，下次运行补发。登录启动默认关闭，用户可开启。首版不安装独立Windows服务，不承诺电脑关机时提醒。

## 6. 技术与数据结构

推荐 Tauri 2 + React + TypeScript + Vite；Rust负责业务规则、SQLite、重复生成、提醒调度和系统集成，前端负责展示与交互。使用rusqlite（bundled SQLite）、chrono/chrono-tz、serde、UUID、tracing及Tauri通知/单实例/登录启动/对话框插件。版本在工程创建时固定并提交Cargo.lock和前端锁文件；Rust版本必须满足选定插件要求。

架构：React界面 → Tauri类型化命令 → Rust任务服务 → SQLite；Rust后台调度使用相同任务服务和事务，通过事件通知界面刷新。前端不直接读写数据库，不承担后台计时。IPC返回统一结构化错误，禁止以HTML执行任务备注。磁盘操作仅允许用户选择的导入导出位置及应用数据目录。

| 表 | 关键字段与约束 |
| --- | --- |
| tasks | UUID、title、note、priority、planned_date、due_date、due_time、status、completed_at、deleted_at、series_id、occurrence_date、schedule_revision、created_at、updated_at |
| recurrence_series | UUID、模板内容、daily/weekly/monthly、开始/结束日期、weekday/month_day、时区、active、推进游标 |
| subtasks | UUID、task_id、title、completed、sort_order |
| reminder_rules | task_id或series_id、提前天数集合、提醒本地时刻 |
| reminder_jobs | UUID、task_id、revision、offset_days、trigger_at_utc、pending/claimed/submitted/cancelled、retry_at、last_error；唯一(task_id, revision, offset_days) |
| reminder_inbox | 批次UUID、任务引用、触发时间、读取状态、系统提交结果 |
| settings / schema_migrations | 主题、时区、默认09:00、登录启动偏好、备份格式及迁移版本 |

数据放在Tauri解析的应用数据目录，不写入安装目录。启用外键、事务、WAL及busy timeout，写入经单一数据库服务串行调度。标题去除首尾空白后长度1–200字符、备注最多20,000字符、优先级低/普通/高，默认普通；日期仅接受真实日历日期。

导出采用SQLite备份API产生一致快照，不能直接复制运行中的主数据库文件。JSON格式包含schema_version、任务、模板、子项、设置及重复推进信息；不携带可再次发送的旧通知队列。首版恢复采用替换模式，校验文件、备份当前库、暂停调度，在成功后重建提醒；损坏文件不得改变现有数据。数据库迁移前自动快照，失败停止写入并提供恢复入口。

## 8. 验收标准与重点风险

1. 离线完成任务录入、修改、完成与恢复，重新启动后全部保留；保存失败明确告知，不显示虚假成功。
2. 本日/本周/本月/指定日期共享任务；跨年周、闰年2月、跨月周、全天截止边界正确。
3. 正常运行且系统允许通知时，提醒在计划时间后60秒内提交系统；关闭窗口后仍提交。
4. 睡眠跨过提醒后，恢复60秒内提交一条合并摘要；完成/删除任务不会参与补发。
5. 每月31日连续生成1月31日、2月末、3月31日；多次重启不重复生成；长期离线分批恢复无卡死。
6. 修改截止时间、模板或时区不再提交旧提醒；单期编辑与后续系列编辑不破坏已完成历史。
7. 导出恢复后任务与重复规则一致；损坏导入不会清空现有数据，恢复成功后不轰炸历史通知。
8. 第二次启动激活现有窗口；退出关闭数据库与后台；升级安装保留用户数据。
9. 在记录配置的Windows测试机上，10,000条任务首次可交互目标≤3秒，查询刷新p95≤200毫秒；达不到时先分析分页、索引和序列生成，再确定发布门槛。

最高风险是通知在安装版中的身份注册与系统行为、重复任务积压、日期/时区边界、修改后旧提醒竞态、恢复与迁移的数据损失。依次在早期系统验证、唯一约束与分批生成、可注入时钟、事务与revision、备份与故障注入中验证。
