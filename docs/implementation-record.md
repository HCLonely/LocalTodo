4. 系统通知和任务修改使用同一互斥数据库服务，发送前核对任务状态与版本，避免改期后发送旧提醒。系统提交与落库之间崩溃时仍可能重复一次。
5. 恢复备份保持当前登录启动偏好，避免恢复数据时隐式修改系统启动行为。用户可在设置中显式调整。
6. 恢复旧备份为系列记录提醒起点，后台补齐历史实例时不重新提交历史通知。
7. 分批生成与查询共享核心服务。每批最多100条，任务列表每页50条；后台无需前端计时器。
8. 将安装工具缓存和临时目录置于工程所在盘，规避Windows打包时的跨盘/加密目录移动失败。
