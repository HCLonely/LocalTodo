## 实施决定补充

- 系列同源ID与完成日期排除集使用可缺省字段，兼容旧JSON备份；付出的代价是系列生成和导入需检查排除记录。
- 超过1000条的离线提醒取消旧批量上限以保证一个合并摘要；超大积累会占用更多内存，后台生成仍分批让出数据库锁。
- JSON导出引入tempfile作为运行依赖，实现同盘原子替换；SQLite快照继续使用SQLite备份API。

真实WebView2回归额外发现Tauri覆盖的window.confirm返回Promise，且旧同步调用未等待答案；改为显式dialog.confirm异步接口，开启allow-message权限，失败按取消处理。Native UI Automation实际按取消和继续，验证草稿保护与父任务完成；组件测试覆盖异步取消/异常/确认。

补全已确认的提醒预览：提前3/1/0天显示实际日期及提醒时刻、应用时区；扩展原提醒测试先观察缺少预览的失败再实现。20项Rust与11项前端完整验证再次通过。

通知领取状态采用持久化pending加数据库服务互斥；重启会直接恢复pending，未单独设置claimed租约。因此崩溃恢复无需等待60秒，但仍存在系统提交与落库之间的重复窗口，已在验收限制中说明。

ZIP采用新的空白暂存目录，仅包含exe、启动卡片cmd、说明和空data目录。重建不会清除正在使用的data目录，也不会将其放入ZIP。旧安装数据保留，需要时从JSON导入。

实际发布测试发现Tauri2.12.1的from_config只接受相对dataDirectory，绝对路径被忽略。因此关闭自动窗口创建，在setup内用WebviewWindowBuilder.data_directory显式构建两个窗口。源码证据：tauri/src/webview/mod.rs的from_config路径检查；[窗口配置文档](https://v2.tauri.app/reference/config/)。必须通过WebView2实际进程user-data-dir核对，不能只依赖配置文件。
